# ReadySetJob UI/UX 디자인 레퍼런스 및 통합 설계 방향 (DESIGN_REFERENCES)

* 작성일 및 출처 확인 기준일: 2026-11-10
* 대상 프로젝트: ReadySetJob (채용 및 인턴십 지원 관리, 불변 버전 기반 자기소개서 관리, 경험 자료실, 대시보드 통계 웹 애플리케이션)
* 기술 환경: Express + EJS 서버 사이드 렌더링(SSR), Vanilla CSS / Pretendard 웹폰트, Chart.js

---

## 1. 핵심 UI/UX 레퍼런스 상세 분석

ReadySetJob은 **파이프라인 추적(칸반 및 테이블)**, **장문 문서 작성 및 버전 비교(자기소개서 에디터)**, **데이터 시각화(통계 대시보드)**의 세 가지 성격을 동시에 지닌다. 이를 유기적으로 결합하기 위해 글로벌 표준으로 꼽히는 SaaS 및 문서 도구 6종(Linear, Huntr, Craft, Attio, Notion, Pretendard 한국어 타이포그래피 체계)을 조사했다. 공식 엔지니어링 블로그 및 도움말 문서에서 확인된 사실과, 공개 문서에 구체적 픽셀 토큰이 명시되지 않은 항목(`공식 수치 확인 불가`)에 대한 실무 UI 설계 기준치를 명확히 구분해 기술한다.

### 1.1 Linear (linear.app): 미니멀 SaaS 레이아웃과 시각적 절제

#### 관찰 가능한 UI/UX 패턴
* **역 L자형(Inverted L-shape) 애플리케이션 크롬 구조**:
  * Linear의 2024년 UI 리디자인(`How we redesigned the Linear UI (part II)`)과 2026년 3월 디자인 리프레시(`A calmer interface for a product in motion`)는 좌측 고정 사이드바와 상단 뷰 헤더가 본문 캔버스를 감싸는 역 L자 구조에 집중한다.
  * 좌측 사이드바는 워크스페이스 전환, 핵심 뷰 탐색, 하위 섹션을 좁은 폭(일반적인 데스크톱 SaaS 구현 기준 약 220px~244px 범위, 공식 문서는 정확한 픽셀 고정값 대신 아이콘·레이블·버튼의 수평 및 수직 정렬 정교화로 설명) 안에 정렬한다.
  * 2026년 리프레시에서는 사용자가 목적지 화면에 도착한 뒤 탐색 UI가 본문 콘텐츠와 시선을 다투지 않도록 사이드바의 배경 톤을 한층 차분하게 낮추고, 불필요한 팀 아이콘 배경색을 제거했다.
* **LCH 색공간 기반 테마와 저채도 중립 표면**:
  * 기존 HSL 색상 체계에서 테마당 98개 변수를 수동 정의하던 방식을 버리고, 지각적 균일성(Perceptual Uniformity)을 갖춘 **LCH 색공간** 기반 생성 규칙(`Base color`, `Accent color`, `Contrast` 3개 핵심 입력값으로 전체 표면·텍스트·아이콘·컨트롤 토큰 생성)으로 전환했다.
  * 2024년 개편에서 푸른 기운을 줄여 중립성을 높였고, 2026년 개편에서는 차가운 청회색 대신 채도가 낮은 따뜻한 무채색(Warm Neutral Gray) 계열로 기본 라이트 및 다크 테마를 정돈했다.
* **경계선(Border)과 그림자(Shadow)의 절제**:
  * 무거운 드롭 섀도 대신 `1px solid`의 저대비 경계선과 미세한 배경 명도 차이로 영역(사이드바, 본문 리스트, 우측 속성 패널)을 분리한다.
  * 2026년 개편에서는 의미 없이 중복된 구분선을 덜어내고 경계선 대비를 낮춰, 구조는 유지하되 선이 콘텐츠보다 먼저 눈에 띄지 않도록 조정했다.
* **고밀도 리스트 및 타이포그래피 위계**:
  * 서체는 제목용 **Inter Display**와 본문 및 인터페이스용 **Inter**로 역할을 분리한다(개별 폰트 크기의 공식 픽셀 토큰 명세는 공개 글상 확인 불가이나, 웹 SaaS 리스트 표준인 본문 13px~14px, 보조 메타데이터 12px, 단정한 단일 행 높이 36px~40px 수준으로 높은 정보 밀도를 유지).
  * 본문 영역은 리스트, 칸반 보드(`Cmd/Ctrl + B`로 전환), 분할 화면에 동일한 정렬 규칙을 적용하고, 이슈나 프로젝트의 메타 속성은 우측 슬라이드 패널(Details Pane, `[` 또는 `]` 단축키로 토글)로 분리한다.
* **키보드 퍼스트(Keyboard-first) 인터랙션**:
  * 화면에 모든 버튼을 나열하는 대신 `Cmd/Ctrl + K` 명령 메뉴(Command Menu)로 모든 액션을 검색 및 실행한다. `/`로 검색, `C`로 생성, `F`로 필터, `J`/`K`로 항목 이동 등 키보드 중심 탐색을 제공한다.

#### ReadySetJob에 채택할 점 (Adopt)
* **역 L자 내비게이션과 차분한 사이드바**: 좌측 사이드바(폭 220px~240px)는 오프화이트 톤으로 차분하게 가라앉히고, 우측 메인 캔버스를 밝은 흰색 표면으로 띄워 지원 현황과 자기소개서 본문에 시선이 집중되게 한다.
* **1px 저대비 보더 중심의 레이아웃 구획**: 카드와 패널에 과도한 그림자를 쓰지 않고 `1px solid` 테두리와 표면 명도 차이만으로 정갈한 격자 구조를 만든다.
* **리스트 및 보드 뷰의 일관된 상단 필터 바**: 뷰 헤더에 검색창, 단계 및 결과 필터, 정렬 옵션을 한 줄(높이 44px~48px)로 압축 배치한다.

#### 피해야 할 점 (Avoid)
* **단축키에만 의존하는 숨겨진 액션**: Linear는 숙련된 개발팀 도구이므로 마우스 버튼을 숨겨도 무방하지만, 대학생 및 취업 준비생이 쓰는 ReadySetJob에서는 `새 지원 공고 추가`, `버전 저장`, `이 버전으로 복원` 같은 핵심 액션을 화면 상에 명시적인 버튼으로 노출해야 한다.
* **영문 전용 타이포그래피 스케일의 기계적 복제**: Inter 전용 자간 음수값(`-0.02em` 이하)을 한글에 그대로 적용하면 글자가 뭉치므로 한국어 환경에 맞는 Pretendard 스케일로 재조정해야 한다.

  * A calmer interface for a product in motion: https://linear.app/now/behind-the-latest-design-refresh

### 1.2 Huntr (huntr.co): 구직 트래커 칸반 보드와 지원 카드 아키텍처

#### 관찰 가능한 UI/UX 패턴
* **단계별 수평 칸반 보드(Job Board)**:
  * 화면 전체를 수평 스크롤 가능한 열(Column/List)로 구성한다. 기본 열은 `Wishlist`, `Applied`, `Interview`, `Offer`, `Rejected`의 5개이며, 각 열 헤더에는 단계 이름과 해당 단계에 속한 카드 개수 배지, 열 메뉴(`...`), 카드 추가(`+`) 버튼이 자리한다.
  * 카드를 다른 열로 드래그 앤 드롭하면 단순히 위치만 바뀌는 것이 아니라, 지원 완료나 면접 진입 같은 주요 구직 활동(`Activities`)이 자동으로 타임라인에 기록된다.
  * 카드에 마우스를 올리면 체크박스가 나타나 복수의 지원 건을 일괄 이동(`Move`)하거나 삭제(`Delete`)할 수 있는 플로팅 액션 바가 활성화된다.
* **지원 공고 카드(Job Card) 타일과 상세 모달**:
  * 보드 위의 카드 타일은 기업명, 직무명(Job Title), 카드 구분 색상, 지원 마감일(Deadline) 등 단계 판단에 꼭 필요한 요약 정보만 간결하게 노출한다.
  * 카드를 클릭하면 화면을 이탈하지 않고 상세 모달(Job Card Modal)이 열리며, 그 안에서 원문 공고 URL, 근무지, 급여, 직무 설명(Job Description), 지원 및 면접 기록(`Log Application`, `Log Interview`), 연결된 제출 문서(`Documents`), 활동 타임라인(`Timeline`)을 관리한다(모달 내부의 세부 픽셀 치수와 탭 순서는 공식 문서상 확인 불가).
* **전환 퍼널과 구직 통계(Job Search Metrics)**:
  * `Job Search Funnel`을 통해 `Jobs Saved` → `Applications` → `Interviews` → `Offers`로 이어지는 단계별 전환 실적과 백분율(%)을 시각적으로 보여준다.
  * 특히 현재 칸반 보드 열에 놓인 단순 카드 개수와, 특정 기간 내 실제 활동 이력을 기준으로 집계하는 전환 퍼널을 개념적으로 구분하여 구직자의 실질적인 통과율을 보여준다.

#### ReadySetJob에 채택할 점 (Adopt)
* **칸반 열 헤더의 단계명 + 건수 배지 + 빠른 추가 패턴**: `서류`, `코딩테스트`, `과제`, `1차 면접`, `2차 면접`, `최종`의 6개 열 헤더 우측에 현재 카드 수(예: `4`)를 고정폭 숫자로 표시한다.
* **카드 타일의 핵심 정보 압축**: 칸반 카드 표면에는 `기업명`, `직무명`, `합불 결과 배지(진행중/합격/불합격)`, `마감일 또는 다음 일정(D-day)`, `자소서 연결 여부 아이콘`만 배치해 6개 열이 한 화면에 들어와도 답답하지 않게 설계한다.
* **퍼널 기반 전환율 통계**: 대시보드에서 단순 누적 건수뿐 아니라 서류 통과율, 코딩테스트 및 과제 통과율, 면접 통과율을 Chart.js 차트로 시각화한다.

#### 피해야 할 점 (Avoid)
* **`Rejected(불합격)`를 별도 칸반 열로 분리하는 구조**: Huntr처럼 불합격을 독립된 열로 빼면 어느 전형 단계에서 탈락했는지 보드 상에서 즉시 알 수 없다. ReadySetJob은 6개 전형 단계 열을 그대로 유지한 채, 카드 내부의 **결과 상태 배지(`진행중`, `합격`, `불합격`)**와 카드 하단/테두리 톤으로 합불을 구분해야 한다.
* **카드 배경 전체에 원색을 칠하는 색상 구분**: Huntr는 카드별 강렬한 배경 색상 지정을 허용하지만, 이는 화면 전체의 시각적 피로도를 높인다. 색상은 얇은 상태 배지(Pill)나 좌측 3px 액센트 바에만 제한적으로 사용한다.

### 1.3 Craft (craft.do): 문서 중심 에디터 타이포그래피와 보조 패널 분리

#### 관찰 가능한 UI/UX 패턴
* **문서 집필 몰입을 돕는 3영역 역할 분리**:
  * 데스크톱 인터페이스를 **좌측 탐색 영역**(Space 전환, 폴더·태그 분류, 현재 문서의 목차 전환), **중앙 문서 편집 영역**(충분한 여백을 가진 종이 형태의 본문 캔버스), **우측 또는 보조 스타일/도구 영역**(페이지 스타일, 폰트, 배경 등 설정)으로 분리한다.
  * 글을 쓸 때는 좌측 사이드바를 접거나 넓은 페이지 모드로 전환해 중앙 문서 영역에 최대한의 공간과 여백을 돌려준다.
* **문서 타이포그래피와 목차(Table of Contents) 연동**:
  * 앱 UI 크롬의 밀도와 문서 본문의 읽기 편의를 분리한다(macOS 등에서 앱 UI 크기는 고정한 채 문서 본문만 확대/축소 가능).
  * 문서 내 제목(Title), 부제목(Subtitle), 헤딩(Heading)의 시각적 위계가 곧바로 좌측 탐색 패널의 **목차(TOC)** 구조로 자동 반영되어, 긴 문서 안에서 특정 문항이나 섹션으로 즉시 점프할 수 있다(기본 본문 폰트 크기의 공식 토큰 수치는 확인 불가이나, 장문 에디터 표준인 본문 15px~16px, 줄간격 1.65~1.75, 본문 최대 폭 680px~760px 구조에 부합).
* **블록의 페이지화 및 카드(Card) 표현**:
  * 문서 안의 하위 콘텐츠 묶음을 독립된 카드 스타일로 감싸 시각적으로 구획하고, 상위 문서에는 핵심 요약만 남긴 채 클릭 시 상세 내용으로 진입하는 계층 구조를 제공한다.

#### ReadySetJob에 채택할 점 (Adopt)
* **문항 목차(좌) + 중앙 집필 캔버스(중) + 경험 자료 및 버전 이력(우)의 분리**: 자기소개서 에디터 화면에서 중앙에는 폭이 제한된(720px~780px) 깔끔한 문항별 입력 카드를 배치하고, 우측 보조 패널(폭 320px~360px)에서 `경험 자료실 참조`와 `불변 버전 히스토리 목록`을 탭으로 전환하며 열람하게 한다.
* **UI 텍스트와 에디터 본문 텍스트의 타이포그래피 이원화**: 사이드바와 버튼 등 UI 요소는 13px~14px(줄간격 1.4~1.5)로 촘촘하게 유지하되, 자기소개서 작성 textarea 및 버전 Diff 뷰 본문은 **15px, 줄간격 1.7, `word-break: keep-all`**을 적용해 장문 한국어 퇴고 시 눈의 피로를 줄인다.
* **문항 카드 단위 구획과 하단 고정 글자수 바**: 각 자소서 문항(1번 문항, 2번 문항 등)을 독립된 여백과 1px 보더를 가진 블록 카드로 감싸고, 각 문항 카드 하단에 실시간 글자수(`공백 포함 642 / 700자 (91.7%) | 공백 제외 510자`)와 프로그레스 바를 정갈하게 배치한다.

#### 피해야 할 점 (Avoid)
* **배경 그라데이션, 커버 이미지, Washi Tape 등 장식적 스타일링**: Craft가 제공하는 100여 종의 문서 배경 이미지나 그라데이션, 스티커 장식은 포트폴리오나 개인 노트에는 어울리지만, 글자수 계산과 버전 비교가 핵심인 자기소개서 에디터에서는 가독성을 해치므로 배제한다.

## 2. ReadySetJob 통합 디자인 원칙 (Unified Design Principles)

세 가지 목업 방향성(A안, B안, C안)은 정보 배치와 레이아웃 우선순위에서 서로 뚜렷이 구별되지만, 제품 전체의 시각적 일관성과 완성도를 보장하기 위해 아래 **6대 통합 디자인 원칙**을 공통 기반으로 공유한다.

### 2.1 단일 라이트 모드(Clean Light Mode)와 오프화이트 표면 위계
어두운 다크 모드나 화려한 그라데이션 대신, 장시간 한국어 자기소개서를 읽고 다듬기에 가장 편안한 **오프화이트(Off-white) 기반 라이트 모드**로 통일한다. 그림자 대신 배경 표면의 미세한 명도 차이로 깊이(Elevation)를 표현한다.
* **앱 배경 및 사이드바 표면 (`Surface Muted`)**: `#F8FAFC` 또는 `#F7F7F5` (차분한 오프화이트로 탐색 영역과 칸반 배경을 뒤로 물림)
* **기본 작업 카드 및 에디터 표면 (`Surface Primary`)**: `#FFFFFF` (지원 카드, 통계 위젯, 자기소개서 작성 영역을 선명하게 부각)
* **보조 입력창 및 호버 표면 (`Surface Subtle`)**: `#F1F5F9` (필터 버튼 호버, 테이블 헤더, 비활성 탭 배경)

### 2.2 섬세한 1px 테두리(`1px solid`)와 절제된 그림자
* 모든 카드, 패널, 테이블, 입력 필드는 `1px solid #E2E8F0` (또는 `#E5E7EB`)의 얇고 정갈한 경계선으로 구획한다.
* 기본 상태의 카드에는 그림자를 쓰지 않거나 극도로 옅은 그림자(`0 1px 2px rgba(15, 23, 42, 0.04)`)만 부여하고, 마우스 호버나 드래그 중인 칸반 카드, 모달 및 드로어에만 절제된 Elevation 그림자(`0 4px 12px rgba(15, 23, 42, 0.08)`)를 사용한다.
* 모서리 반경(Border Radius)은 버튼·배지·입력창에 `6px`, 카드·패널·모달에 `8px`을 일관되게 적용한다.

### 2.3 단일 브랜드 액센트 컬러와 의미론적(Semantic) 상태 색상
화면 전체의 85% 이상을 무채색(Slate/Neutral Gray)으로 유지하고, 주요 행동 유도(Primary CTA)와 활성 상태에만 **단일 액센트 컬러**를 사용한다. 전형 결과와 Diff 비교 색상은 의미가 즉시 전달되도록 저채도 배경 + 고대비 텍스트 쌍으로 엄격히 제한한다.

| 토큰 역할 | 배경색 (Background) | 텍스트/아이콘색 (Foreground) | 보더색 (Border) | 적용 대상 |
| :--- | :--- | :--- | :--- | :--- |
| **Primary Accent** | `#2563EB` (또는 `#4F46E5`) | `#FFFFFF` | `#1D4ED8` | 주요 저장/생성 버튼, 활성 탭 인디케이터, 선택 포커스 링 |
| **Accent Soft** | `#EFF6FF` | `#1D4ED8` | `#BFDBFE` | 현재 선택된 사이드바 메뉴, 현재 진행 단계 강조 |
| **Result: 진행중** | `#F1F5F9` | `#475569` | `#CBD5E1` | 결과 미확정, 서류/면접 대기 상태 배지 |
| **Result: 합격 (Pass)** | `#ECFDF5` | `#047857` | `#A7F3D0` | 전형 합격 배지, Diff 추가된 텍스트(`<ins>`) 하이라이트 |
| **Result: 불합격 (Fail)** | `#FEF2F2` | `#B91C1C` | `#FECACA` | 전형 불합격 배지, 마감 초과 경고, Diff 삭제된 텍스트(`<del>`) |
| **Warning / D-Day 임박** | `#FFFBEB` | `#B45309` | `#FDE68A` | 마감 D-3 이내 임박 배지, 글자수 95%~100% 근접 알림 |

### 2.4 Pretendard 기반 한국어 타이포그래피 및 숫자 정렬 규칙
* **기본 폰트 패밀리**: `"Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont, system-ui, sans-serif`
* **UI 텍스트와 에디터 본문의 명확한 스케일 분리**:

| 타이포그래피 계층 | 크기 (`font-size`) | 굵기 (`font-weight`) | 행간 (`line-height`) | 적용 위치 및 규칙 |
| :--- | :--- | :--- | :--- | :--- |
| **페이지 타이틀 (H1)** | `20px ~ 22px` | `600 (SemiBold)` | `1.35` | 상단 뷰 제목, 지원 기업 상세 타이틀 (`letter-spacing: -0.01em`) |
| **섹션/모달 헤더 (H2)** | `16px` | `600 (SemiBold)` | `1.4` | 대시보드 차트 카드 제목, 자소서 문항 제목 |
| **자소서 에디터 본문** | `15px` | `400 (Regular)` | `1.7` | 자기소개서 textarea, 버전 비교(Diff) 본문 (`word-break: keep-all`) |
| **기본 UI / 카드 제목** | `14px` | `500 ~ 600` | `1.45` | 칸반 카드 기업명, 테이블 행 본문, 입력 폼 텍스트 |
| **보조 UI / 내비게이션** | `13px` | `500 (Medium)` | `1.4` | 사이드바 메뉴, 버튼 레이블, 필터 칩, 직무명 |
| **메타데이터 / 캡션** | `12px` | `400 ~ 500` | `1.35` | 날짜, D-day, 글자수 카운터, 단계별 건수 배지 (`tabular-nums` 필수) |

### 2.5 단계(6-Stage)와 결과(Pass/Fail)의 시각적 분리 원칙
* 칸반 보드의 **가로축 열(Column)**은 오직 채용 전형 단계(`서류` → `코딩테스트` → `과제` → `1차 면접` → `2차 면접` → `최종`)만 나타낸다.
* 각 카드의 **합불 결과(`진행중`, `합격`, `불합격`)**는 카드 우측 상단의 캡슐 배지로 표시하며, `불합격` 처리된 카드는 열을 이동시키지 않고 해당 단계 열 내부의 하단으로 정렬하거나 투명도(`opacity: 0.72`)를 낮춰 "어느 단계에서 탈락했는지" 시각적 맥락을 보존한다.

### 2.6 불변(Immutable) 버전 비교와 실시간 글자수 피드백
* 자기소개서 에디터에서 저장 버튼을 누를 때마다 `v1`, `v2`, `v3`와 같이 타임스탬프와 버전 메모가 포함된 불변 스냅샷이 생성된다.
* 버전 비교(Diff) 모드에서는 기준 버전(예: `v2`)과 비교 버전(예: `v4`)을 선택하면 문항별로 삭제된 어절은 연한 적색 배경과 취소선(`<del>`), 추가된 어절은 연한 녹색 배경과 굵은 글씨(`<ins>`)로 렌더링하며, 우측 상단의 `이 버전으로 복원(새 버전 생성)` 버튼으로 안전하게 되돌릴 수 있다.

## 3. 세 가지 목업(Mockup) 설계 방향성 (A안 / B안 / C안)

위 통합 디자인 원칙을 공유하면서도, 사용자의 핵심 작업 흐름과 정보 배치 우선순위에 따라 뚜렷이 구별되는 3가지 목업 방향성을 제시한다.

### 3.1 [A안] Linear 기반 미니멀 SaaS형 (고밀도 워크스페이스 & 슬라이드오버 중심)

```text
+-----------------------------------------------------------------------------------+
| [사이드바 220px] | [단일 뷰 헤더 48px: 브레드크럼 | 검색(/) | 단계·결과 필터 | +공고] |
| - 대시보드       +----------------------------------------------------------------+
| - 지원 현황 보드 | [메인 작업 캔버스: 고밀도 6열 칸반 또는 분할 에디터]              |
| - 자소서 보관함  | +--------+ +--------+ +--------+ +--------+ +--------+ +-----+ |
| - 경험 자료실    | | 서류 4 | | 코테 2 | | 과제 1 | | 1차 2  | | 2차 1  | |최종1| |
| - 공고 북마크    | +--------+ +--------+ +--------+ +--------+ +--------+ +-----+ |
|                  | | [카드] | | [카드] | | [카드] | | [카드] | | [카드] | |[카드| |
|                  | +--------+ +--------+ +--------+ +--------+ +--------+ +-----+ |
+-----------------------------------------------------------------------------------+
```

* **핵심 콘셉트**: Linear와 Attio의 정교한 역 L자형 크롬 구조를 적용해 화면 여백 낭비를 최소화하고, 한 화면 안에서 최대한 많은 지원 건과 문항 상태를 빠르게 스캔 및 조작하는 **고밀도 전문가용 SaaS 방향**이다.
* **화면별 레이아웃 및 정보 배치**:
  1. **대시보드**:
     * 좌측 고정 사이드바(`220px`) + 우측 메인 영역 구조다.
     * 상단 1행에 **4열 초소형 KPI 스트립**(전체 지원 수, 서류 통과율, 현재 진행중 전형 수, 이번 주 마감/면접 수)을 높이 `76px`의 얇은 1px 보더 카드로 나열한다.
     * 중단 2행은 좌측 `60%` 영역에 Chart.js **6단계 전형별 생존/탈락 누적 막대 차트**를, 우측 `40%` 영역에 **합불 비율 도넛 차트**를 배치한다.

* **화면별 레이아웃 및 정보 배치**:
  1. **대시보드**:
     * 좌측 접이식 내비게이션(`200px`)과 넓은 중앙 다큐먼트 스타일 캔버스로 구성된다.

     * **중앙 종이형 문서 캔버스(최대 폭 `760px`, 좌우 넉넉한 여백)**: 따뜻한 오프화이트 배경(`#F7F7F5`) 위에 순백색(`#FFFFFF`) 문항 시트가 떠 있는 형태다. 각 문항 블록 하단에는 정밀한 글자수/바이트 게이지(`공백 포함 680자 / 700자 | 공백 제외 542자`)가 자리한다.
     * **2열 나란히 보기(Side-by-Side) 및 인라인 버전 비교(Diff) 뷰**: 우측 인스펙터(`340px`)에서 과거 불변 버전(예: `v2 초안`)을 선택하면, 중앙 캔버스가 즉시 **이전 버전 vs 현재 버전 비교 뷰**로 전환되어 문항별로 삭제된 문구(`#FEE2E2` 배경)와 다듬어진 문구(`#DCFCE7` 배경)를 선명하게 대조하고 `이 버전으로 복원`을 실행할 수 있다.
     * **우측 경험 자료실 및 AI 질문 인스펙터(`340px`)**: 본인이 정리해 둔 경험 자료(STAR 기법: 상황, 과제, 행동, 결과 요약 카드)를 검색해 옆에 띄워 두고 문장을 옮겨 적거나, 작성된 문항을 기반으로 AI 예상 면접 질문 카드를 바로 뽑아볼 수 있다.

  * Diff Added (`<ins>`): `#DCFCE7` (Text `#166534`) | Diff Removed (`<del>`): `#FEE2E2` (Text `#991B1B`)
